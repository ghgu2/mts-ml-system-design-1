# Результаты проверки ДЗ 3

Проверено 21 октября 2026 на ARM64, Docker, Airflow 2.10.5 / Python 3.11.11. Использован включённый пример из 12 000 строк. SHA-256 исходного примера и сводка проверок находятся в [checks.json](checks.json).

## Сквозной сценарий

Команда `docker compose run --rm --no-deps verify` завершилась успешно. Она запускала реальные DAG через API Airflow и отправляла сообщения в Kafka. Плановые прогоны тоже выполнялись; все сохранённые прогоны трёх DAG успешны, см. [state_before_restart.json](state_before_restart.json).

Первая Kafka-проба получила `model_version=m201903`, последняя — `m201908`. Скор изменился с 0.0951829704 до 0.0453331517. Сообщения и решения quality gate сохранены в [verification.json](verification.json).

Кандидаты за май, июнь и июль не прошли gate. Например, у майской модели ROC-AUC улучшился, но Average Precision упал, поэтому версия не была опубликована. Августовская модель прошла оба условия на одном и том же августовском проверочном наборе:

| Метрика | Действующая m201903 | Кандидат m201908 |
|---|---:|---:|
| Average Precision | 0.7999826172 | 0.8533730443 |
| ROC-AUC | 0.9746091489 | 0.9978853404 |

Это проверка поведения gate на учебной симуляции: новые месяцы создаются из уже известных размеченных строк. Такие значения не являются оценкой обобщения модели на новых реальных транзакциях.

[scoring.log](scoring.log) содержит загрузку обеих версий одним контейнером и ответы на пробы. [runtime_before_restart.json](runtime_before_restart.json) фиксирует время старта контейнера до обеих загрузок и `restart_count=0`. Отдельно после этого выполнен `docker compose down` / `up -d` без удаления томов: курсор `2019-09-01`, 72 000 строк и действующая `m201908` сохранились, см. [state_after_restart.json](state_after_restart.json).

Все 10 правил DQ прошли. Сохранён [HTML-отчёт](dq_latest.html), опубликованный отдельным ручным прогоном `check_data_quality`. Снимок состояния контейнеров после повторного запуска — [containers.txt](containers.txt).

## Автоматические и регрессионные проверки

15 тестов прошли внутри финального образа Airflow, включая разбор DAG и связывание аргументов задач. Проверены rollback поставки, отсутствие дублей, восстановление после падения между заменой указателя и SQL commit, запрет отката старой задачей, отклонение модели, hot reload, сохранение рабочей пары при повреждении нового комплекта, отсутствие target leakage, временной split, retention и HTML при ошибках DQ. Сводка — [tests.txt](tests.txt).

Конфигурации Compose всех трёх заданий валидны. `docker-compose.hw1.yml` совпадает с исходным Compose предыдущего коммита; файлы ДЗ‑2 не изменены. Проверка зависимостей финального образа Airflow (`pip check`) не нашла конфликтов.
